# Verification

Every claim the README makes, with the command behind it and the evidence produced. Nothing here is
inferred from reading source; each row is a command that ran.

Reproduce the whole thing with one command:

```powershell
powershell -File tools\run_full_chain.ps1 -IL <IsaacLab> -WBT <whole_body_tracking> -Repo <this-repo>
```

Reference machine: Windows 11, NVIDIA T1200 Laptop GPU (4 GB VRAM, driver 596.47), 16 logical
processors, Isaac Sim 6.1.0-rc.26, Isaac Lab 3.0.0-dev, Python 3.12.15, torch 2.11.0+cu130,
rsl-rl-lib 5.5.1, wandb 0.28.0.

## Key evidence per claim

### The patch applies cleanly and reproduces the working state

```
git -C <pristine worktree at cd65172> apply --check <patch>   → exit 0
git -C <pristine worktree at cd65172> apply          <patch>   → exit 0
13 files changed, +488 −184
```
Each of the 13 files was compared byte-for-byte against the working repository (after newline
normalisation, because Git's `core.autocrlf` converts LF→CRLF on checkout): **0 mismatches**.

### No unintended parameter drift

`scripts/diff_against_upstream.py` compares the resolved config against upstream values:

```
ENV CONFIG    fields compared: 32   identical: 28
  EXPECTED: num_envs 4096->64, contact history_length 3->2, two debug_vis True->False
  UNEXPECTED drift: none
AGENT CONFIG  fields compared: 16   identical: 16
  UNEXPECTED drift: none
RESULT: PASS - no unintended drift
```

`scripts/check_agent_cfg_equivalence.py` proves the deprecated `policy=` +
`empirical_normalization=True` configuration migrates to the same values as the modern
`actor`/`critic` form: 55 fields compared, **6 differences, all benign** — four legacy distribution
fields that `_update_distribution_cfg` never reads because `distribution_cfg` is already set, and
`obs_groups`, which the legacy path auto-fills to the same value.

### Quaternion handling

Legacy (WXYZ, no marker) and modern (XYZW, `quat_order` marker) motion files load to identical
values:

```
original xyzw quat[0,0] : [1.74e-04, -1.52e-02, -1.60e-05, 9.99884e-01]
legacy on-disk quat[0,0]: [9.99884e-01, 1.74e-04, -1.52e-02, -1.60e-05]   (w first)
loaded modern           : [1.74e-04, -1.52e-02, -1.60e-05, 9.99884e-01]
loaded legacy           : [1.74e-04, -1.52e-02, -1.60e-05, 9.99884e-01]
IDENTICAL: True
```

A modern file generated by `make_synthetic_motion.py` has `body_quat_w[0] = [1.7e-04, -1.5e-02,
-1.6e-05, 0.99988]` — scalar part last, confirming XYZW.

### Training produces real artefacts

`logs/rsl_rl/g1_flat/<timestamp>/` contains `model_0.pt` and `model_2.pt` (6,768,511 bytes each),
`run.json`, `events.out.tfevents.*`, and `params/{agent,env}.yaml`. The dumped `agent.yaml` shows
`obs_groups: {actor: [policy], critic: [critic]}`, `actor/critic.obs_normalization: true`, and the
full 12-field PPO configuration matching upstream.

### Motion ONNX export

```
inputs : {'obs': [1, 160], 'time_step': [1, 1]}
outputs: ['actions','joint_pos','joint_vel','body_pos_w','body_quat_w','body_lin_vel_w','body_ang_vel_w']
metadata keys: ['action_scale','anchor_body_name','body_names','command_names','default_joint_pos',
                'joint_damping','joint_names','joint_stiffness','observation_history_lengths',
                'observation_names','run_path']
ALL CHECKS PASSED
```

`validate_exported_onnx.py` (onnxruntime 1.26.0, no simulator) checks the graph contract, the
metadata keys, that the embedded motion equals the source `.npz` **compared by body name**, and that
`time_step` clamps correctly past the final frame. Body index map measured:
`[0,4,10,18,5,11,19,9,16,22,28,17,23,29]`, matching the configured 14 bodies.

### W&B upload includes the external weight file

The artifact manifest was inspected directly from the offline run's transaction file:

```
manifest contains motion_policy     : True
manifest contains policy.onnx       : True
manifest contains policy.onnx.data  : True
```

The `policy.onnx.data` line is the regression test for a real bug: `Artifact.add_file(onnx_path)`
alone omits the external-weight sibling, producing an artifact that cannot be loaded. The upload now
globs `<onnx_path>*`. The guard against calling `upload_to_wandb` with no active run was also
exercised and raised `RuntimeError` as intended.

### Capsule collision conversion

```
XML parses : robot
capsules   : 28 | cylinders: 0 | spheres: 1
joints/links: 39 / 40
```
`<visual>` geometry untouched (0 cylinders there; 35 meshes). Mass values, joint count and link count
identical to the source URDF. Both the cylinder and capsule variants were trained end to end
(`exit 0`), and variant selection was verified for auto / `capsule` / `cylinder`.

### URDF path resolution

Four paths exercised: no `WBT_SOURCE` (resolves via the installed package), `WBT_SOURCE` set,
explicit `--urdf`, and a bogus path (clear error, exit 1).

## Deliberately not verified

| item | why |
|---|---|
| Live upload to a W&B project | Needs credentials. The offline path is verified; the network path is not. |
| `csv_to_npz.py` end to end | No source CSV is available on this machine. Its quaternion reordering and hard-coded `/tmp` path were fixed, but the conversion itself was never run. |
| Training on real motion data | The only bundled motion is a synthetic stand-still clip. |
| rsl_rl 2.x vs 5.5.1 numerical behaviour | No 2.x source was available to diff against. Only *this project's* configuration was proven equivalent. |
| Playback running to completion | Blocked by the framework issue in KNOWN-ISSUES §5c. |
| Paper-level training quality | `num_envs` is 64 rather than 4096 because of a 4 GB GPU. This dominates every API difference in effect. |
